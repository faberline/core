# DDD P2 downstream checks

Checked on 2026-10-01. All checks used the same fixed local snapshots.
Their live working trees were not edited. Only the temporary clones' Cargo.lock files
were reset to the snapshot contents before applying each core path override.

- Core P1 baseline: `f15b896fe1dbba00fc4b4ecc0d4debb8eefacd67`.
- Core P2 source revision: `244c147a249fc07d5696a2cd3389e5ac314c250a`. Later commits only organize tests and finish documentation.
- Command: `cargo check --offline --workspace --all-targets --message-format=short`.
- For each of the 30 core packages, the check added a Cargo `patch` config
  for `https://github.com/faberline/core` that pointed to the selected local core tree.
- Downstream default features were used. This is not an all-feature downstream gate.

P1 passed in all 17 repos. With P2, meter passed and 16 repos need migration.
The first compile reported 506 diagnostics. Some are in a Git dependency,
such as relay used by defer. They are counted in the build that reported them.
The compiler can stop before it finds every required change.
After migration, each maintainer must run the repo's own feature and acceptance gates.

Core has not tagged a release containing P2. Apply these changes when moving
the core pin to a revision that contains P2. This report is information;
it does not authorize changes to a downstream repo.

See [the complete API migration guide](ddd-p2.md) and
[the P1 to P2 source-path table](ddd-p2-paths.md).
